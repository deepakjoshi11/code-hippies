SECTION 0 — HOW THE CROSS-LINKING WORKS (read this first)
--------------------------------------------------------------------------------

You asked for the Deepak Joshi <-> Code Hippies link to be SEO-effective but
subtle. Those two goals are in tension, and the resolution is structural rather
than textual.

The mistake to avoid: repeating "Deepak Joshi, professionally known as Code
Hippies globally" in five places. It reads as keyword stuffing to a human, and
LinkedIn's own search ranking discounts repetition within a profile. It makes
you look like you are trying.

What actually works instead — entity association:

  1. STRUCTURED FIELDS DO THE HEAVY LIFTING.
     LinkedIn's Experience section creates a machine-readable link between a
     person and a Company Page. When your personal profile lists "Code Hippies"
     as an employer and that entry resolves to the actual Company Page, the
     association is established in LinkedIn's graph. No prose needed. This is
     the single highest-value action in this document and it is a dropdown,
     not a sentence.

  2. SAY THE ALIAS ONCE, PROPERLY, IN THE ONE PLACE IT IS EXPECTED.
     The first line of your About section. One clean sentence. Search engines
     weight early body text; humans read the first line and stop. Saying it
     once with confidence reads as fact. Saying it four times reads as anxiety.

  3. LET THE OTHER MENTIONS BE INCIDENTAL.
     Everywhere else the name appears, it should appear because the sentence
     needed it — "the Code Hippies studio ships...", "built under Code
     Hippies" — not because you are placing a keyword. If you can delete the
     brand name and the sentence still makes sense, you placed it well; if the
     sentence collapses, it was load-bearing and it stays.

  4. CONSISTENCY BEATS FREQUENCY.
     Use the exact string "Code Hippies" everywhere — same spacing, same
     capitalisation — across LinkedIn, GitHub, the website and the email
     signature. Entity resolution works on exact matches. "CodeHippies",
     "code hippies" and "Code-Hippies" fragment the signal.

A note on "globally". Your brief said "professionally called code hippies
globally". The honest version of that is that you work with clients
internationally from India — which src/data/bio.ts already states as "Based in
India — working globally". The copy below uses that framing. A claim that the
name is globally *recognised* is not something either of us can support yet,
and on a profile that recruiters and clients verify, an unsupportable claim is
a liability rather than an asset. Once there is a portfolio of international
clients to point at, this gets easier to say and truer at the same time.

SECTION 4 — WHAT NOT TO WRITE
--------------------------------------------------------------------------------

The site's entire premise is that every claim it makes is checkable. A LinkedIn
profile that breaks that premise undermines the site it points at, because the
same person is being assessed in both places.

Do not write:
  - Client counts, revenue figures, traffic numbers or performance percentages
    that were not measured. No "increased traffic by 300%".
  - Testimonials or client quotes. None have been collected. The testimonials
    array on the site is deliberately empty; keep the profile consistent.
  - "Award-winning", "industry-leading", "world-class", "10x". Unverifiable,
    and they read as filler to exactly the technical readers you want.
  - Years of experience you cannot evidence.
  - Any claim that the AI assistant cannot hallucinate. It is
    retrieval-grounded with a refusal path, which reduces fabrication
    substantially and makes the failure mode visible. That is the accurate
    claim and it is a stronger one, because it survives scrutiny.
  - Technologies you have not shipped. The Skills section is the first thing a
    technical interviewer probes.

Safe to say, because it is verifiable today:
  - Twelve client sites live and publicly checkable.
  - Ex-Deloitte USI.
  - Founder of Dharmarthlabs.
  - The specific stacks listed in the case studies.
  - The retrieval-grounded assistant with a refusal path and CI evaluation.
